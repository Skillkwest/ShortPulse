# Security Checklist

Purpose: ensure user isolation and authenticated access across the Next.js app + internal API stack.

## Current expectations

- Supabase client uses persisted sessions, auto-refresh tokens, and explicit PKCE browser auth flow (`auth.flowType = "pkce"`) so new auth callbacks use authorization codes instead of bearer-token URL fragments.
- Frontend redirects authenticated sessions to the dashboard after sign-in/sign-up.
- SQL runbook reference: `docs/sops/sop_sql_migration_operations.md`.

## Required controls

- **RLS**: Enable Row-Level Security on Supabase tables; policies should enforce `user_id = auth.uid()` for select/insert/update/delete on user-owned tables (`projects`, `project_workspace_states`, `project_output_display_items`, `project_prompt_items`, `project_generation_items`, `media_folders`, `ai_generations`, `generation_attempts`, `ai_generation_outputs`, `generation_publications`, `generation_projection`). `media_files` and `media_prompts` should enforce owned select/update/delete, but authenticated inserts must also require `user_has_paid_media_library_access(auth.uid())` so baseline-access accounts cannot add Media Library or Reference Grid rows. Membership tables (`media_folder_media_items`, `media_folder_prompt_items`) should enforce user-scoped select/insert/delete. `media_events` allows select + insert only. Control-plane inbox tables such as `generation_observation_inbox` should remain service-role-only, and claim RPCs such as `claim_generation_observation_inbox_batch` must stay `SECURITY DEFINER` with `service_role`-only execute grants.
- **AI Studio workflow reload metadata**: Keep `generation_projection.workflow_reload` user-scoped with the parent `generation_projection` row and treat it as restore metadata only. It may mirror into `ai_generations.metadata` and generated `media_files.metadata` for traceability, but it must not become pricing, ownership, provider-routing, or authorization authority.
- **AI Studio error payload detail**: Keep `generation_projection.error_payload` user-scoped with the parent `generation_projection` row and use it only for failed generated-output detail views and diagnostics. It must not become customer-visible compact card/banner copy, pricing authority, ownership authority, or provider-routing input.
- **AI Studio generated-output workspace restore scope**: Keep `generation_projection.workspace_runtime_key` user-scoped with the parent `generation_projection` row and use it only as bounded non-project Reference Grid restore scope. It must not authorize provider status/result access across users, must not replace `project_id` on project routes, and must not re-enable user-global plain-session generated-output startup hydration.
- **Project workspace freshness guard**: Keep `project_workspace_states.snapshot_updated_at` server-authoritative and preserve the newest durable snapshot when autosave completions arrive out of order. Keep `project_workspace_states.checkpoint_revision` monotonic for structural checkpoint changes, and keep `project_output_display_items.source_snapshot_updated_at` from letting older compatibility snapshots overwrite newer per-output display records. Older client payloads must degrade to a no-op rather than overwriting newer workspace or display state.
- **Public schema Data API grants**: Do not rely on implicit Supabase auto-exposure for new `public` tables, routines, or sequences. Add explicit least-privilege grants in the same migration that creates the object. Missing grants block PostgREST/GraphQL/supabase-js access before RLS policies run. Service-role-only control-plane tables should explicitly revoke `public` / `anon` / `authenticated` and grant only `service_role`.
- **Billing tables**: Keep `billing_profiles`, `billing_subscription_contracts`, `billing_subscription_storage_addons`, `billing_subscription_change_intents`, `billing_subscription_scheduled_changes`, `ai_credit_balance`, `ai_credit_ledger`, `ai_credit_grants`, and `ai_credit_grant_allocations` isolated per user (`user_id = auth.uid()`). `billing_profiles`, `billing_subscription_contracts`, subscriber storage add-on rows, subscription-change intent rows, and scheduled subscription-change rows must remain read-only to customer sessions; only trusted server/webhook paths may mutate plan/customer/subscription linkage, subscriber contract terms, storage add-on contract terms, subscription-change intent proof, Stripe schedule projections, credit grant lots, credit allocation rows, or `max_concurrent_generations` entitlement snapshots. `billing_plan_offers` and `billing_storage_addon_offers` may be public-read but must remain service-role-only for writes, and manual-review storage add-ons must not be activated for public self-serve checkout. Do not allow users to self-credit with positive ledger rows.
- **Admin storage economics snapshots**: Keep `admin_storage_usage_snapshots` service-role-only. The admin storage workspace is currently parked, and `/api/admin/storage-economics` plus `/api/admin/storage-usage-snapshots` must return their deactivated responses before admin auth, Supabase reads, or snapshot writes. A future reactivation lane may expose provider usage economics only through trusted admin-only API responses after `requireAdminUser`; no customer role should receive direct table grants or RLS policies for Supabase plan, egress, compute cost, or observed overage data.
- **Model pricing control plane**: Keep `model_pricing_policy_versions`, `model_pricing_policy_runtime`, and `model_pricing_policy_events` service-role-only for reads/writes. Customer sessions may read the active policy only through trusted authenticated API routes, never by direct table access or direct RPC execute grants.
- **Legal policy control plane**: Keep `legal_policy_versions`, `legal_policy_runtime`, and `legal_policy_events` service-role-only for reads/writes. Public legal pages may render active policy content only through trusted server-side route resolution, and admin mutations must flow through `/api/admin/legal/policies/[slug]/publish` with `requireAdminUser`, service-role RPC execution, slug allowlisting, and stale-write protection.
- **Create Pulse built-in control plane**: Keep `create_pulse_builtin_runtime` service-role-only for reads/writes. Customer sessions may read the active built-in catalog only through `/api/ai/create-pulse-builtins`; only trusted admin routes may mutate it through `/api/admin/agent-instructions/pulse-builtins`. Built-in Pulse definitions must not be sourced from or persisted back into `user_preferences.ai_studio_saved_pulses`. Customer runtime reads must fail closed when the live control-plane catalog is unavailable or degraded; seeded fallback is admin visibility/recovery context, not a customer runtime authority.
- **Expert Edit system preset control plane**: Keep `expert_edit_system_preset_runtime` service-role-only for reads/writes. Customer sessions may read the active global Edit preset catalog only through `/api/ai/expert-edit-system-presets`; only trusted admin routes may mutate it through `/api/admin/agent-instructions/edit-system-presets`.
- **Built-in Styles control plane**: Keep `ai_studio_builtin_style_runtime` service-role-only for reads/writes. Customer sessions may read the active global built-in Styles catalog only through `/api/ai/built-in-styles`; only trusted admin routes may mutate it through `/api/admin/agent-instructions/built-in-styles`. Built-in Style definitions must not be sourced from or persisted back into `user_preferences.ai_studio_style_details_overrides`; that preference remains custom-style-only while `user_preferences.ai_studio_deleted_style_ids` may hide built-ins per user. Customer runtime reads must fail closed when the live control-plane catalog is unavailable or degraded; seeded fallback is admin visibility/recovery context, not a customer runtime authority.
- **Admin stats RPC hardening**: Keep `get_admin_global_stats_summary()`, `list_admin_model_usage_stats(integer)`, `get_admin_global_stats_v1()`, `get_admin_generation_breakdown_v1()`, `get_admin_growth_stats_v1()`, `get_admin_growth_cohorts_v1()`, `get_admin_first_value_funnel_v1()`, and `get_admin_error_events_summary_v1(timestamptz, timestamptz, timestamptz)` service-role-only. They aggregate `app_error_events` telemetry plus generation/project/media/billing/attribution analytics and must never be exposed directly to anon/authenticated client roles.
- **App-error telemetry retention boundary**: Keep `app_error_event_telemetry_daily_rollups` service-role-only and treat it as aggregate telemetry history, not an incident table or customer-facing analytics authority. Raw `app_error_events` retention must run only through the approved rollup/prune function so low/medium telemetry is aggregated before pruning, high-severity telemetry and non-telemetry incidents are preserved, and manual troubleshooting does not delete forensic rows.
- **Browser crash-session boundary**: Keep `browser_crash_sessions` and both crash-session RPCs service-role-only. Authenticated clients may write session-health events only through `/api/log/browser-session`; Chrome Reporting API crash delivery may use public `POST /api/browser-crash-report`, but that route must be body-limited, rate-limited, and correlation-only. Both routes must mutate through `record_browser_crash_session_event_v1`; native reports may update an existing row by allowlisted `CrashReportContext` session id and must not create anonymous crash rows. Admins may read only through `/api/admin/crashes`. The ingest metadata allowlist may preserve low-cardinality lifecycle, stall, pressure, memory-ratio, item-count, bounded media-work counters, and browser crash-report evidence for crash review, but must exclude prompts, DOM text, signed URLs, raw storage paths, provider payloads, stack traces, raw query values, and arbitrary browser data. This table must not become a general analytics/event sink or a replacement for `app_error_logs` / `app_error_events`.
- **Growth attribution isolation**: Keep `growth_attribution_identities` service-role-only. Anonymous/browser attribution writes must flow only through trusted server routes; customer sessions must never query or mutate attribution rows directly.
- **Public growth ingest allowlist**: `/api/telemetry/growth` may accept unauthenticated requests only for the explicit `telemetry.marketing.*`, `telemetry.auth.*`, and `telemetry.billing.*` source allowlist. Do not turn it into a general-purpose public event sink, and keep downstream telemetry/attribution failures behind stable generic public errors instead of returning raw database, provider, auth, or environment details.
- **Client credit reads**: Query credit tables with an explicit per-user filter (`user_id = current user id`); never use unscoped fallback reads like `.limit(1)` on shared relations.
- **Ledger integrity**: Enforce credit underflow protection at the database layer so debits cannot push balances below zero.
- **Credit grant-lot integrity**: Subscription allocations must be represented as expiring `ai_credit_grants` lots with a 60-day `expires_at`; paid top-up lots must keep `expires_at = null`. Reservations and direct debits must allocate from grant lots in expiring-first order, and expiration must run only through the service-role-only `expire_credit_grants(integer)` RPC.
- **Schema parity**: Keep `ai_credit_ledger` columns aligned with app expectations (`source`, `source_ref`, `metadata`, `created_by`) or run `sql/migrate_ai_credit_ledger_legacy_to_v2.sql` before enabling admin credit operations.
- **Reservation lifecycle**: Keep `ai_credit_reservations` + reservation RPC functions aligned with app expectations (run `sql/migrations/002_add_generation_credit_reservations.sql` before enabling production generation billing).
- **Provider request ownership**: Status/result proxy routes must only accept provider request IDs (`requestId`/`taskId`) when ownership is explicitly proven for the caller. Reject both cross-user IDs and unknown/untracked IDs; record provider request IDs at submit time (`markSubmitted`) so ownership checks are enforceable.
- **Webhook idempotency**: Persist Stripe event IDs (`stripe_event_log`) and skip duplicates before applying credits/subscription updates. Keep `stripe_event_log` service-role-only.
- **Webhook size limits**: Enforce bounded raw-body reads on webhook endpoints and return `413` for oversized payloads before signature parsing or downstream processing.
- **Safe webhook errors**: Do not expose internal transport/database error messages from webhook `500` responses; log internals server-side and return stable generic failures.
- **AI image-analysis intake trust**: Keep active style-analysis intake on authenticated `POST /api/ai/extract-style` `imageDataUrl` input. Do not reintroduce remote-image URL fetch lanes without fail-closed trusted-host checks and explicit allowlisting.
- **Storage isolation**: Keep the `media_library` bucket private; require folder prefixes that start with `auth.uid()` (see `sql/storage_policies.sql`). Private tab uploads must stay under `<auth.uid()>/private/images/...`.
- **Media storage scope**: Keep `media_files.storage_path` constrained to `<user_id>/...` and shape-safe (`no ../`, no backslashes; run `sql/migrations/016_harden_media_storage_path_scope.sql` and `sql/migrations/017_harden_media_storage_path_shape.sql`) and reject out-of-scope paths in service-role media routes before signing or moving objects.
- **Media upload authority**: Prefer the server-authoritative Media Library direct-upload route pair (`/api/media/prepare-upload` -> browser direct storage upload -> `/api/media/finalize-upload`) so destination/source classification and persisted row metadata are derived server-side from validated signatures, not client-declared MIME/classification fields.
- **Media folder ownership**: Folder CRUD and membership operations must reject root-id writes, enforce custom-folder UUID validation, and ensure all membership item ids are user-owned before assign/unassign (`/api/media/folders/*`, `/api/media/prompts/list`, `/api/media/list` folder filter path).
- **Media direct-preview trust**: Default-block external direct-preview hosts. Allow external direct fallback only when explicitly enabled (`SHORTPULSE_MEDIA_ALLOW_EXTERNAL_DIRECT_PREVIEWS`/`NEXT_PUBLIC_MEDIA_ALLOW_EXTERNAL_DIRECT_PREVIEWS`) and host allowlisted (`SHORTPULSE_MEDIA_DIRECT_URL_ALLOWED_HOSTS`/`NEXT_PUBLIC_MEDIA_DIRECT_URL_ALLOWED_HOSTS`). Keep Next image optimizer host usage constrained to trusted hosts only.
- **Media preview repair lookup**: Keep `resolve_media_storage_object_by_basename(uuid, text)` `SECURITY DEFINER` with `service_role`-only execute grants. It may return only one caller-scoped `media_library` storage path for legacy preview repair and must not expose raw storage inventory to browser roles.
- **Supabase image transformation prohibition**: Do not introduce or retain any runtime, preview, detail, fallback, compatibility, or experimental path that depends on Supabase image transformations. This includes `createSignedUrl(..., { transform })`, any `/storage/v1/render/image/` URL construction or rewrite, and any adaptive-media surface that emits Supabase transform URLs. Signed originals, durable local variants, or trusted app-owned non-Supabase optimization paths are the only allowed delivery mechanisms. Any production appearance of Supabase image transformation usage is a regression/incident.
- **Recovery media fetch trust**: Recovery execution must reject provider-returned media URLs unless they resolve through trusted provider hosts or the explicit trusted media host policy. Never allow recovery autosave/persistence fetches to follow arbitrary external result URLs.
- **Media derivative worker boundary**: Keep `/api/internal/media-derivatives/run` cron-secret protected (`x-shortpulse-cron-secret` or bearer secret) and fail-closed when `SHORTPULSE_MEDIA_DERIVATIVES_ENABLED=false`; derivative claim/update RPCs (`claim_media_derivative_batch`, `mark_media_derivative_ready`, `mark_media_derivative_failed`) must remain `SECURITY DEFINER` with service-role-only execute grants.
- **Media storage lifecycle dry-run boundary**: Keep `/api/internal/media-storage-lifecycle/run` cron-secret protected (`x-shortpulse-cron-secret` or bearer secret), fail-closed when `SHORTPULSE_MEDIA_STORAGE_LIFECYCLE_ENABLED=false`, and dry-run only until a separate reviewed delete plan is approved. The diagnostic RPC `get_media_storage_lifecycle_summary(integer)` must remain `SECURITY DEFINER` with `service_role`-only execute grants and must not return object paths or user ids. The `voice_source_lifecycle` proof table, including Voice Changer video-derived `voice-changer/staged-audio` rows, must remain service-role-only and must not become customer quota, voice ownership, or provider access authority.
- **Voice Changer source-video boundary**: Video-derived Voice Changer generation and no-charge retry must accept original video authority only from the authenticated user's private `<user-id>/voice-changer/source-video/` namespace, re-read and verify the stored video signature, and derive MIME from those bytes. Client filenames, MIME hints, signed URLs, and projection rows must not override stored-byte or user-scope authority. `generation_projection.remux_recovery` is a repairable read model only; canonical retry/storage state remains in `ai_generations`, generation publications/outputs, and private media storage.
- **Inactive-account storage proof boundary**: Keep `get_account_storage_ownership_proof_details(integer, uuid, integer)` and `get_account_storage_ownership_proof_summary(integer)` `SECURITY DEFINER` with `service_role`-only execute grants. These RPCs are proof/status diagnostics only: they may report active-user blockers, inactive-looking accounts, deleted Auth rows, or owner-missing storage prefixes, but they must not delete, enqueue deletion, recommend deletion, expose object paths, or become customer/browser payloads. Final inactive-user data deletion remains a separate manual human decision outside this proof system.
- **Fleet health worker boundary**: Keep `/api/internal/admin-user-health-fleet/run` cron-secret protected (`x-shortpulse-cron-secret` or bearer secret) and fail-closed when `SHORTPULSE_USER_HEALTH_FLEET_ENABLED=false`; fleet helper RPCs (`list_admin_user_health_active_targets`, `prune_admin_user_health_history`) must remain `SECURITY DEFINER` with service-role-only execute grants.
- **Internal comp billing boundary**: Keep `/api/admin/billing/contracts/update` admin-only and `/api/internal/billing-contract-renewals/run` cron-secret protected (`x-shortpulse-cron-secret` or bearer secret) with fail-closed enable flags. Internal comp contract writes must remain server-only/service-role-only and must not rely on client-controlled plan or credit mutations. Keep scheduler auth aligned between `SHORTPULSE_INTERNAL_BILLING_RENEWALS_CRON_SECRET` and the Supabase Vault secret used by `sql/configure_internal_billing_renewal_scheduler_supabase.sql`.
- **Credit expiration worker boundary**: Keep `/api/internal/credit-expirations/run` cron-secret protected (`x-shortpulse-cron-secret` or bearer secret) and disabled unless `SHORTPULSE_CREDIT_EXPIRATIONS_ENABLED=true`. The worker may only call the service-role-only expiration RPC and must not accept client-selected users, grant ids, raw ledger payloads, or arbitrary SQL mode switches.
- **Character table isolation**: Keep RLS enabled on `characters`, `character_reference_packs`, `character_reference_images`, `character_quick_swap_items`, `character_media_assets`, and `character_generation_jobs` with strict `user_id = auth.uid()` policies (run `sql/migrations/008_add_character_manager_foundation.sql`, `sql/migrations/045_add_character_quickswap_deck.sql`, and `sql/migrations/068_add_character_media_assets_isolation.sql`).
- **Elements table isolation**: Keep RLS enabled on `elements`, `element_reference_sets`, and `element_media_assets` with strict `user_id = auth.uid()` policies and dedicated `<user_id>/elements/...` storage scope checks. Do not reuse character tables, character storage paths, or character cleanup flows for Elements (run `sql/migrations/080_add_elements_library_foundation.sql`).
- **Media source integrity**: Keep `media_files.source` constrained to `upload | private_upload | ai_studio | character_reference | character_generation | character_quickswap`, enforce non-null/default semantics, and keep private/character path checks aligned (run `sql/migrations/003_add_private_media_source.sql`, `sql/migrations/004_add_private_media_integrity_checks.sql`, `sql/migrations/007_harden_media_source_and_usage_rpc.sql`, `sql/migrations/010_harden_character_reference_media_integrity.sql`, and `sql/migrations/045_add_character_quickswap_deck.sql`).
- **Media usage aggregate**: Keep `get_media_library_usage_bytes()` available for authenticated users so usage UI can avoid partial totals from paged caches.
- **Media storage entitlement helpers**: Keep `resolve_media_storage_usage_bytes(uuid)`, `resolve_media_storage_base_limit_bytes(uuid)`, and `resolve_media_storage_addon_limit_bytes(uuid)` service-role-only. They accept explicit user ids and run as `SECURITY DEFINER`; authenticated customers must use `get_media_storage_quota_summary()`, which derives `auth.uid()` internally.
- **Frontend route protection**: Guard `/profile`, `/report-issue`, `/ai-studio`, `/ai-studio/*`, `/admin`, and `/admin/*`; redirect unauthenticated users to `/log-in`.
- **Browser session restore protection**: Logout must mark a non-sensitive local invalidation epoch and clear local Supabase session authority before network signout settles. Protected routes must force-refresh Supabase auth on mount and `pageshow` before private content can paint from stale React/browser state. Already-mounted protected routes must also force-refresh auth when a hidden tab becomes visible again, but that visible-tab revalidation should run in place without remounting protected workspace state; if the session is missing or predates the logout epoch, it must clear local session authority and redirect to `/log-in`. The public root must stay session-aware while stored auth is unresolved, and signup-mode entry with an existing prior session must return to the default authenticated landing path instead of silently honoring a protected `next` target.
- **Auth callback token exposure**: New browser auth flows must use PKCE authorization-code callbacks rather than implicit bearer-token fragments. Keep `/auth/callback` return paths same-origin and fail closed when callback artifacts are missing or invalid. Any temporary support for token-fragment callbacks must be treated as migration compatibility only, with hosted auth smoke coverage and a removal condition.
- **Public signup launch gate**: Public signup is open by default at the app layer; set `NEXT_PUBLIC_SHORTPULSE_PUBLIC_SIGNUP_ENABLED=false` only as an emergency close switch. Supabase Auth production config must have the Before User Created hook enabled before provider-level signup is opened; app routing alone cannot stop direct Supabase Auth API or OAuth-provider signup when the provider allows new users. For launch, apply `sql/migrations/164_add_paid_signup_intent_gate.sql`, `sql/migrations/165_account_first_signup_intent_gate.sql`, `sql/migrations/166_grant_signup_hook_schema_usage.sql`, and `sql/migrations/167_add_google_ip_signup_intent.sql`, enable Supabase Auth's Before User Created hook on `public.hook_shortpulse_signup_intent(event jsonb)`, then allow `disable_signup=false` while leaving `NEXT_PUBLIC_SHORTPULSE_PUBLIC_SIGNUP_ENABLED` unset/true. `/api/auth/signup-intent` must create only short-lived intents for safe account-first or paid pricing return paths unless the emergency close switch is false: email/password signup uses hashed-email matching, while Google signup ignores visible email/password form fields and uses the Google-only short-lived IP-bound match from ADR 0097. The hook must reject email/password or Google user creation without a matching pending intent before `auth.users` insertion. Signup intents must not grant credits, plan value, or Stripe entitlement; new users start at zero credits, `/api/account/bootstrap` may create or sync only Stripe customer identity, and paid access remains owned by `/api/billing/subscription/change` and Stripe webhook projection. Verify the emergency closed state with `NEXT_PUBLIC_SHORTPULSE_PUBLIC_SIGNUP_ENABLED=false` plus `npm -C frontend run auth:signup-config -- --project-ref <production-ref>` and the approved launch state with `npm -C frontend run auth:signup-config -- --project-ref <production-ref> --expect-enabled`, plus hosted hook tests.
- **Zero-credit account-first entitlement boundary**: Account-first signup is expected to create a real active Supabase user and a real active Stripe customer identity that can enter AI Studio on baseline access, but the balance must remain exactly zero until paid billing authority adds value. Baseline access is not a free plan, trial, subscription, or paid entitlement. Signup, `/api/account/bootstrap`, Stripe customer sync, login, and AI Studio navigation must never create credits, paid storage, concurrency, subscription state, generation entitlement, Media Library insert authority, or Reference Grid insert authority. Credits may enter an account only through Stripe-backed subscription/webhook projection or an approved credit top-up flow for an established paying account; zero-credit users must be blocked at billable generation submit time and media/reference save time rather than funded implicitly.
- **Suspicious non-Stripe account removal**: Before deleting unknown or non-Stripe Auth users, run `npm -C frontend run auth:audit-non-stripe-accounts -- --email <target>` or `--user-id <target>` and classify the footprint. Delete through the Auth-root admin path only after confirming whether the account is a zero-footprint delete candidate or whether Stripe, credits, reservations, generations, media, projects, voices, or storage objects require cleanup review first.
- **Admin user deletion fail-closed**: `/api/admin/users/[userId]` must refuse Auth deletion while billing identity, credit balance, reservations, generations, media rows, projects, custom voices, or media storage objects still exist. Do not bypass this route with direct Auth deletion unless a separate reviewed cleanup/reconciliation plan is approved for that exact account.
- **Key management**: Never expose the service-role key. Use only the anon key in the browser.
- **Local agent credential boundary**: During the pre-launch phase, local agent/operator credentials may live only in ignored local credential files such as `.env.agent.local` or `frontend/.env*.local` so agents can access the production/staging environments for supervised development. Those files must remain untracked and must never be uploaded to GitHub, copied into docs, pasted into reports, or converted into tracked temporary exports.
- **Browser storage-state boundary**: Never commit Playwright/browser storage-state files, Supabase auth localStorage payloads, refresh tokens, access tokens, signed Supabase storage URLs, or identity-linked network captures. Raw screenshots, JSON packets, storage-state dumps, and network captures belong only in ignored local evidence caches; tracked evidence must be redacted manifests and human-readable reports.
- **Secret exposure response**: If credentials are exposed in chat logs, temp files, or commits, rotate and replace affected keys immediately (staging then production), revoke old keys, and follow `docs/sops/sop_secret_exposure_rotation.md`. Record incident evidence in the appropriate retained operator artifact and update `docs/change_log.md` when repo-visible operator procedure changes.
- **Network calls**: All Supabase requests already include the user’s JWT; avoid any other unauthenticated calls for user-owned data.
- **API auth boundary**: Require authenticated bearer tokens for provider proxy routes (`/api/fal/*`, `/api/openai/*`, `/api/elevenlabs/*`, `/api/ai/*`), Kie upload helpers (`/api/kie/*`), project routes (`/api/projects/*`), pricing routes (`/api/pricing/*`), media routes (`/api/media/*`), `/api/report-issue*`, upload endpoints, billing routes, and admin routes (enforced in `frontend/proxy.ts`, with additional route-level guards where needed).
- **Route-level auth checks**: Keep `requireApiUser`/`requireAdminUser` in sensitive API handlers even when `frontend/proxy.ts` already guards the prefix, so auth still fails closed if middleware configuration drifts.
- **Autosave policy authority**: AI Studio recovery execution and direct ElevenLabs audio generation routes must read `user_preferences.media_autosave_enabled` before background persistence and skip `media_files` inserts when preference is OFF; manual save remains allowed.
- **Preset panel preference isolation**: Expert Edit preset preferences persisted in `user_preferences.expert_edit_preset_panel_ids`, `user_preferences.expert_edit_custom_presets`, and `user_preferences.expert_edit_deleted_system_preset_ids` (with legacy fallback reads from `expert_edit_preset_panel_labels`) must remain protected by `user_id = auth.uid()` RLS isolation and only be written through authenticated user context. Global Edit system presets must not be stored in or hydrated from these per-user columns; `expert_edit_deleted_system_preset_ids` may only hide/restore system preset visibility for one user, and user-side preset editing must remain limited to custom preset slots.
- **Pulse preset preference isolation**: AI Studio Pulse preferences persisted in `user_preferences.ai_studio_create_pulse_panel_ids`, `user_preferences.ai_studio_saved_pulses`, and `user_preferences.ai_studio_deleted_builtin_pulse_ids` must remain protected by `user_id = auth.uid()` RLS isolation and only be written through authenticated user context. `ai_studio_saved_pulses` is reserved for per-user custom Pulses; `ai_studio_deleted_builtin_pulse_ids` may only hide/restore built-in visibility for one user, and global built-in guided-workflow definitions belong to the admin control plane instead.
- **Styles library order preference isolation**: Shared Styles order persisted in `user_preferences.ai_studio_style_panel_ids` must remain protected by `user_id = auth.uid()` RLS isolation and only be written through authenticated user context.
- **Styles library deletion preference isolation**: Styles Library deletions persisted in `user_preferences.ai_studio_deleted_style_ids` must remain protected by `user_id = auth.uid()` RLS isolation and only be written through authenticated user context.
- **Styles library details preference isolation**: Styles Library detail overrides persisted in `user_preferences.ai_studio_style_details_overrides` must remain protected by `user_id = auth.uid()` RLS isolation and only be written through authenticated user context. This column is for user-created custom Styles only; global built-in Styles are admin-owned records from `ai_studio_builtin_style_runtime` and must not be user-editable.
- **Saved voice preference isolation**: AI Studio custom voices persisted in `user_preferences.ai_studio_saved_voices` must remain protected by `user_id = auth.uid()` RLS isolation and only be written for the authenticated owner through trusted server or authenticated user context.
- **Custom voice ownership enforcement**: Treat `user_owned_custom_voices` as the authoritative ElevenLabs custom-voice ownership ledger. Shared provider workspace inventory or provider categories like `generated`/`cloned` must never be enough to list, use, or delete a custom voice for another user. `GET /api/elevenlabs/voices`, `DELETE /api/elevenlabs/voices/:voiceId`, `/api/elevenlabs/text-to-speech`, and `/api/elevenlabs/speech-to-speech` must fail closed when caller ownership is not proven, and create/clone routes must roll back provider/sample artifacts when authoritative ownership persistence fails. `user_preferences.ai_studio_saved_voices` may continue to mirror compatibility metadata, but legacy rows must not be treated as custom-voice ownership unless they reconcile to `user_owned_custom_voices`, and legacy-migrated/disputed ownership rows must remain out of the runtime access boundary until they are explicitly repaired.
- **Media compliance acceptance isolation**: One-time compliance records persisted in `user_media_compliance_acceptances` must remain user-scoped (`user_id = auth.uid()` for any direct client reads/inserts), while the protected-route agreement check/save flow stays behind authenticated `/api/account/media-compliance` server handling.
- **Issue report admin boundary**: Keep `user_issue_reports` and `user_issue_report_screenshots` RLS-enabled with no direct browser policies; keep `issue_report_screenshots` private. Screenshot uploads may only use `/api/report-issue/screenshots/prepare` signed upload targets, final writes must flow through authenticated `POST /api/report-issue` after storage verification, and all reads/mutations must flow through `/api/admin/reports*` with `requireAdminUser` plus service-role Supabase access. Serve screenshots to admins with short-lived signed original URLs only; do not use Supabase image transformations. Preserve report history through status/notes updates instead of normal hard deletion.

Automated writes must flow through `POST /api/internal/tester-reports/ingest` with `SHORTPULSE_TESTER_REPORT_INGEST_SECRET`; admin reads must flow through `/api/admin/tester-reports` with `requireAdminUser` plus service-role Supabase access; Hybervees review-state mutations must flow through `/api/admin/tester-reports-review` with `requireAdminUser` plus service-role Supabase access. - **Media compliance recovery semantics**: Protected-route consent checks must distinguish `consent required`, `auth recovery required`, and `consent service unavailable`. A stale/invalid session must not render as a consent-content requirement, and degraded consent persistence/auth verification dependencies must fail as a stable unavailable state rather than leaking raw internal errors.
- **Character client local persistence isolation**: Browser-local Character Manager persistence keys, including the selected character id, must be namespaced by authenticated `user_id` to prevent cross-account leakage on shared browsers.
- **Token-first route auth**: `requireApiUser` must verify bearer identity server-side and must not authorize from `x-shortpulse-*` headers alone. Proxy headers are advisory only and must not supply admin/app metadata or other authorization fields when the verified token payload omits them.
- **Auth callback return-path safety**: Auth `next` values for signup, password reset, email-change, and post-login redirects must stay same-origin relative paths. Reject absolute URLs, protocol-relative paths, auth self-redirects, and backslash-containing paths before building callback URLs or calling router navigation. Google OAuth callbacks must carry `provider=google` before `/auth/callback` may treat provider cancel/back outcomes as benign returns to `/auth`; email confirmation, recovery, and email-change callbacks must remain fail-closed when their artifacts are missing or invalid.
- **Email-change confirmation error safety**: `/api/account/email/confirm` must derive identity from the verified bearer session, attempt Stripe sync only after Supabase confirms the email-change callback, log downstream billing/provider failures server-side, and return the confirmed auth email without raw Stripe, database, customer id, or environment-mode details.
