| `/ai-studio`                   | Yes           | Creative canvas (prompt/image/video)                         | `/creator-studio` forwards here. Session identity contract uses `?sid=<uuid>` as runtime identity only; plain `/ai-studio` starts a new session id via shallow replace. Legacy AI Studio session save/restore is hard-disabled by default pending the future Projects system, so `sid` no longer guarantees resumable workspace restoration. When `?projectId=<uuid>` is present, AI Studio resolves the owned project record before restore continues, fails closed on invalid or cross-user project ids, treats the visible Media Library project title as `projects.title` authority instead of session-local title state, and loads/saves the current snapshot envelope through `/api/projects/[projectId]/workspace` instead of the legacy remote `sid` snapshot route. Project routes also suppress browser-global workflow-settings, chat-mode, and selected-character local-storage persistence so the project workspace snapshot becomes the restore authority for the current session-snapshot envelope; broader live generated-output authority cleanup remains a later migration phase. Beginner mode is temporarily force-disabled and toggle controls are hidden by runtime policy flags. Expert Edit is now the only Edit workflow surface. The generic Canvas workspace is no longer exposed as a primary AI Studio toolbar workflow, but the top-right `Canvas` header toggle now shows and hides the shared right-rail Canvas section across the four primary workflows (`Create`, `Edit`, `Video`, `Sound`) alongside `Quick Slot Inventory` and `Reference Grid`; the Canvas section defaults off on first load, and Media Library folder canvases remain separate secondary surfaces. Set `NEXT_PUBLIC_AI_STUDIO_MARKUP_MODEL_LOCK_ENABLED=true` to lock Markup tool model branding/submission to Pulse Markup v1 (disabled by default). Set `NEXT_PUBLIC_AI_STUDIO_MARKUP_COLLAPSED_OPEN_MODAL_ENABLED=true` to prototype collapsed `Tools` opening expanded Markup modal directly; closing modal re-collapses tools (disabled by default). Set `NEXT_PUBLIC_AI_STUDIO_MARKUP_STROKE_SECONDARY_REFERENCE_ENABLED=true` to attach a second Markup-only reference input containing flattened layers plus markup strokes when strokes are present (disabled by default). Set `NEXT_PUBLIC_AI_STUDIO_EDIT_GENERATION_MODE_TOGGLE_ENABLED=true` to show a selector-row Standard/Inpaint/Markup generation mode toggle (disabled by default). Expert Edit prompt supports direct references to the primary drop zone via `@main` plus secondary-slot references via `@img1`, `@img2`, and `@img3`, including drag-to-insert from secondary reference slots plus an anchored picker that highlights the primary tile, opens from bare `@` or `Tab` when references exist, cycles with `Tab`, and inserts the selected token on `Enter`. When `NEXT_PUBLIC_STUDIO_AGENT_DIRECT_OPENAI_BYPASS_ENABLED=true`, the Create chat lane defaults to the backend-gated direct OpenAI bypass and can forward staged image attachments as multimodal input so users can ask for image descriptions that return generation-ready prompts. Expert Create `Pulse` mode now mounts an interactive left-rail Pulse Presets card with pinned preset chips, drag/drop from a `More Presets` popup, and saved Pulse definitions pulled from the same per-user library used by the `Pulses` section inside `Libraries -> Presets`. Pulse preset records still persist guided-runtime metadata for built-in and advanced cases (`systemInstructions`, `runtimeMode`, `activationMode`, optional `starterAssistantMessage`, optional `workflowStageHints`, `outputMode`, `memoryPolicy`), but the active product contract is GPT-style: custom Pulses are authored primarily through `Preset Name` plus `System Instructions`, and clicking any pinned Pulse starts it immediately as an isolated Pulse session on `/api/ai/studio-agent`. Pulse mode is state-isolated from Standard mode, exposes an explicit `Deactivate Pulse` control for ending the active Pulse session, and guided Pulses can return step-by-step assistant turns before any final prompt artifact. The primary `Sound` button now lands on `Voice` by default. `Sound -> Voice` opens a dedicated left-panel Voices workflow surface with a top voice library, bottom script composer, and right-rail `Voiceover` / `Voice Changer` controls; it no longer shares the generic Sound panel state. `Sound -> Music` opens a dedicated left-panel Music workflow surface with a split music-library/composer layout plus music-specific composition, arrangement, energy, and output controls. `Sound -> Sound Effects` opens a dedicated left-panel Sound Effects workflow surface with a split sound-effects library, prompt-only composer, and ElevenLabs-backed `Duration`, `Loop`, `Prompt Influence`, and `Format` controls. The embedded Character properties panel is the primary character-management host and now lands on `Character Profile` first instead of `Manage Characters`. The inline Expert Edit `Layers` panel now sits in the left rail directly below `Prompt Presets`. Double-clicking image/video references in the Reference Grid or Quick Slot Inventory opens the detail modal, where `Save` persists that media into `All Media` and appears to the left of `Download`. `Libraries -> Media Library` opens a first-class left-panel Media Library tool (`media-library`) with root/custom folders and media+prompt ingestion; `All Media` remains the master folder with root tabs (`All Media`, `Images`, `Videos`, `Audio`, `Prompts`) inside the same folder surface. The aggregate `All Media` tab shows saved media cards plus saved prompt cards in a mixed masonry feed, `Images`/`Videos` preserve true aspect ratio, `Prompts` renders text cards, `Audio` remains a placeholder, near-bottom infinite scroll auto-load remains on media tabs with one global root media paginator footer retained as manual fallback, right-click media ingests to the Reference Grid, and double-clicking image/video cards opens a preview-only detail modal. `NEXT_PUBLIC_AI_STUDIO_MEDIA_LIBRARY_GESTURE_V2_ENABLED` controls drag-ghost + root right-click ingest + root permanent delete behavior. Per-custom-folder canvas spaces are always enabled, but now follow the same authority split as folder CRUD: non-project surfaces persist via `/api/ai/media-folder-canvas/[folderId]` + `/api/ai/media-folder-canvas/save`, while project routes persist via `GET|PUT /api/projects/[projectId]/media/folders/[folderId]/canvas`. Set `NEXT_PUBLIC_AI_STUDIO_MEDIA_LIBRARY_PANEL_ENABLED=false` to use the legacy modal fallback. `Libraries -> Elements` opens a first-class left-panel Elements Library tool (`elements`) with two embedded modes: `Manage Elements` and `Element Profile`. New elements stage locally inside `Element Profile` and only persist into the Elements library after `Save Element`; profile photos and reference slots remain save-gated until that first explicit save completes. `Libraries -> Styles` opens a primary left-panel Styles Library of currently loaded styles; while Styles is active, the right rail stays visible in reference-grid-only mode (Canvas/Quick Slot/Styles subpanels hidden). The first style tile is a fixed `None` slot and is not editable, deletable, or reorderable, and the right-rail Styles section mirrors this with the same first `None` option. The primary Styles Library supports drag/drop reordering of custom style-card positions, drag/drop image intake from your computer/Reference Grid/Quick Slot (from visible right-rail surfaces) to auto-create custom styles, and an `Add Style` tile that opens a create-style modal. Direct Canvas image drag-out remains deferred in V1. New-style image intake auto-runs style extraction, populates the modal `Style Prompt`, and applies an extracted style title to new card naming fields (manual prompt editing remains available). Clicking a real style tile in the Styles Library opens an edit modal only and does not change active Create/Edit workflow style; right-rail Styles tile clicks are the workflow style-selection path and auto-close the right-rail Styles panel after selection. When a style is selected in Create/Edit, generation submit appends that style prompt to the hidden submission prompt while preserving the visible user prompt text. `Libraries -> Presets` opens one primary left-panel Presets Library with internal `Pulses` and `Prompt Presets` sections. Built-in starter Pulses are editable and save as personal overrides on stable seeded ids, while custom user-authored Pulses now default to the guided GPT-style contract and appear in Expert Create `Pulse` mode immediately when pinned. The `Prompt Presets` section is sourced from the Expert Edit preset catalog with `Custom 1`, `Custom 2`, and `Custom 3` placeholder tiles plus a full-size `Create New Preset` tile while keeping the right rail visible; clicking a preset tile opens an edit modal for preset name + prompt text, each preset tile includes a top-right delete button with yes/no confirmation for permanent deletion, clicking `Create New Preset` opens create mode for the next custom slot (`Custom 4+`), and saves persist via per-user preset overrides. Hovering a real style tile reveals a destructive `X` delete action with yes/no confirmation; confirmed deletes persist via Supabase-backed preferences. Clicking a real style tile opens an edit modal for `Style`, `Reference Image`, and `Style Prompt`; saves persist via per-user style detail overrides. Active AI Studio video workflows are Kie-only: the model modal surfaces Kie Veo, Kie Kling, Kie Seedance 1.5, Kie Seedance 2, and Kie Seedance 2 Fast lanes. Standard mode still defaults empty-standard-frame state to Kie Veo text-to-video behavior, but the modal also allows manual Kling and both active Seedance families there. If Kling is selected with empty frame slots, the first-frame image becomes required before generation starts. Kie Seedance 1.5 supports prompt-only generation, one-image animation, and first/last-frame generation, and exposes a Seedance-only `fixed_lens` control in video settings. Kie Seedance 2 and Seedance 2 Fast follow the Kling-pattern shot workspace plus linked Character/Element slot UX while compiling into Seedance-native frame and multimodal reference payloads. Kie Kling Standard now exposes `Single`, `Multi`, and `Custom` shot modes. `Single` and `Multi` both use the standard single-shot Kling route with the primary prompt plus first frame and optional last frame. `Multi` is a single-prompt multi-scene writing mode and supports `@ElementName` prompt references. `Custom` is the only true Kling multi-shot mode and submits `multi_prompt[]` using the first frame only. |
