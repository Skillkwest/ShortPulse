## summary of what changed

The bounded hardening patch closed a proxy-manifest drift seam in the launch-critical API auth boundary. `frontend/lib/server/api/protectedApiPaths.ts` now treats `/api/openai/*` and `/api/kie/*` as protected prefixes, so middleware fails closed before the request reaches direct OpenAI image routes or the Kie upload helper. The patch also added regression coverage that scans `pages/api/*` for handlers using `requireApiUser` or `requireAdminUser` and fails if any such route is missing from the protected manifest or webhook exceptions. The security checklist was updated so the documented API auth boundary matches the runtime contract.

Follow-up audit fixes also removed the dead `SHORTPULSE_TRUST_PROXY_AUTH_HEADERS` fallback from live docs and `.env.example`, dropped the unused helper in `authProxyContext.ts`, added `/api/internal/billing-contract-renewals/run` to the central internal-route inventory gate, and added method/disabled/auth regression coverage for that billing renewals worker so its carve-out now matches the other cron-secret internal routes.

## acceptance criteria reached

- Reduced one major security-boundary ambiguity: authenticated provider/upload routes are no longer partially protected only by route-level auth.
- Added targeted validation so future manifest drift on auth-enforced API routes fails in tests instead of waiting for manual release review.
- Removed a misleading live ops contract for a retired emergency auth fallback.
- Brought the internal billing renewals worker up to the same regression-coverage level as the other internal secret-protected routes.
- Kept the work inside the owned write surface with no schema or platform-wide auth redesign.
