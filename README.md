# ShortPulse v1

Short-form analytics and creative workspace surfaces built on Next.js with Supabase auth/storage and internal API routes for provider proxying, billing, uploads, and runtime orchestration.

## Tech

- Frontend: Next.js (pages router), Phosphor icons, modular CSS.
- Auth/storage: Supabase client with persisted sessions, `saved_creators` table, and a private `media_library` bucket.
- Account compliance: authenticated `/api/account/media-compliance` returns and records the caller’s acceptance of the current one-time media agreement for images, audio, and video before protected app routes continue.
- Analytics: In-browser scoring of a demo cohort with user-triggered refresh and filtering controls.
- AI Studio providers: Next.js API routes under `/api/fal/*` proxy active Fal/Kie submit/status requests (server-side keys required). Those public `/api/fal/*` submit/status modules are generated compatibility wrappers backed by the shared inventory in `scripts/lib/fal_route_inventory.js`; update the inventory and run `npm -C frontend run fal:routes:sync` instead of hand-editing wrapper files. Image/edit flows still use Fal-backed families such as Seedream, Nano Banana 2, Nano Banana Pro, FLUX Fill, and Bria background remove, while OpenAI GPT Image 2 now supports both Create -> Image through `POST /api/openai/image-generate` and standard Edit through `POST /api/openai/image-edit`. Those lanes complete synchronously and use server-authoritative GPT Image 2 request-shape credit charging before persistence into the canonical generation/media pipeline. `POST /api/generation/abandon` records a user-owned no-refund abandon marker when a Reference Grid spinner is cleared, closes active local lifecycle rows as hidden terminal failures, suppresses later recovery/publication, and does not attempt provider-side cancellation. Public AI Studio video generation remains Kie-only through `/api/fal/kie-veo-submit`, `/api/fal/kie-veo-status`, `/api/fal/kie-kling-submit`, `/api/fal/kie-kling-status`, `/api/fal/kie-seedance-2-submit`, `/api/fal/kie-seedance-2-status`, `/api/fal/kie-seedance-2-fast-submit`, and `/api/fal/kie-seedance-2-fast-status`.
- AI Studio audio generation: authenticated ElevenLabs routes under `/api/elevenlabs/*` now back the Sound workflows. `/api/elevenlabs/voices` loads live provider voices, merges in the user-scoped saved-voice cache from Supabase, and returns server-authoritative voice-library action metadata so the Voices modal can distinguish protected defaults from local-only `Remove` actions and true provider `Delete` actions. `DELETE /api/elevenlabs/voices/:voiceId` follows that same contract by removing local saved voices when applicable and deleting the upstream provider voice only for user-created/provider-deletable entries. `/api/elevenlabs/text-to-voice/design` and `/api/elevenlabs/text-to-voice/create` power the `Create New Voice` Generate Voice path while persisting created voices into `user_preferences.ai_studio_saved_voices`, `/api/media/stage-voice-clone-source` stages local Clone Voice audio samples under the caller's private `voice-clone/source-audio` namespace, `/api/elevenlabs/voices/clone` creates reusable provider voices from those staged samples, `/api/elevenlabs/text-to-speech` generates voiceover audio, `/api/upload-video` now serves as the stable local-video staging adapter for Voice Changer intake, `/api/media/stage-voice-changer-source` stages local Voice Changer audio files through an authenticated server path, `/api/media/extract-audio` stages extracted WAV audio from trusted stored or signed video references for Voice Changer intake and rejects source videos above the staged extraction ceiling, `/api/elevenlabs/speech-to-speech` generates the final Voice Changer output from a staged `sourceStoragePath`, trusted `sourceUrl`, or compatibility local upload and now also persists a sibling remuxed video output whenever that staged audio came from a video source, `/api/elevenlabs/music` generates prompt-first music tracks from the Music panel controls, and `/api/elevenlabs/sound-effects` generates Sound Effects audio from prompt-driven SFX controls. These executable audio routes enforce catalog-backed approved model ids at request validation time. Those routes now honor `user_preferences.media_autosave_enabled`: when autosave is OFF they still return playable in-session outputs but skip background `media_files` creation.
- AI Studio legacy `sid` session persistence is retired. `sid` remains runtime identity only, `/api/ai/sessions/*` now returns retired responses, and durable restore authority for saved work lives on the Projects workspace path instead of the old session save/restore system.
- Billing account flows: public acquisition pricing for `/`, `/dashboard`, `/landing`, and `/pricing` is loaded server-side from the shared billing catalog snapshot loader in `frontend/lib/server/api/billingCatalog.ts`; logged-out dashboard offer cards are loaded server-side from active `dashboard_offers` rows and capped at four. The authenticated `/api/billing/catalog` route still serves live plan/package/storage catalog data to account-management surfaces such as `/profile`. `/api/billing/subscription/change` drives target-aware plan changes, `/api/billing/storage-addon/change` drives target-aware recurring storage add-on add/remove actions from `/profile?section=storage`, `/api/billing/stripe/subscription-transactions` returns recent Stripe invoice history for the subscription and storage payment-history panels (`?kind=storage` isolates recurring storage add-on charges), `/api/billing/stripe/transactions` powers `/profile?section=transactions` with a unified billing feed across invoice-backed renewals and one-time credit purchases, `/api/billing/stripe/checkout` remains the one-time credit-pack checkout route, and `/api/billing/stripe/webhook` syncs Stripe subscription state back into `billing_profiles`, `billing_subscription_contracts`, and recurring storage add-on rows.
- Projects foundation APIs: authenticated project collection/item/workspace routes under `/api/projects*` now back the dashboard `New Project`, dashboard `Open Projects`, AI Studio left-rail project modal create/open/delete actions, AI Studio project-title authority, project-specific Media Library custom folders, and the project-owned workspace snapshot seam. Dashboard `New Project` and the AI Studio Projects modal both ask for an initial project name, then `POST /api/projects/create` creates a user-owned `projects` row in Supabase with that normalized title. `GET /api/projects?limit=` lists caller-owned projects for the shared saved-project modal and also returns up to four `previewImageUrls` per modal project card derived from the saved workspace snapshot, `GET|PATCH|DELETE /api/projects/:projectId` reads, renames, or permanently deletes one owned project, `GET|PUT /api/projects/:projectId/workspace` loads or saves one caller-owned workspace snapshot, and `/api/projects/:projectId/media/folders/*` owns project-scoped folder CRUD plus membership assignment for saved media and prompts. Preview derivation prefers the first four Quick Slot Inventory images and falls back to the first four visible Reference Grid images only when the quick slot has no image previews, and storage-backed project-card previews are signed against a tiny dedicated thumbnail transform so the modal does not fetch larger preview assets than it needs. AI Studio still coexists with legacy `sid`, but `projectId` now resolves the owned project record before restore proceeds, routes visible Media Library project-title edits through `projects.title`, and switches project routes onto project-owned workspace persistence instead of the legacy remote `sid` snapshot path. Saved media and prompts created from a project route now also attach to that active project through project association tables while the global Media Library inventory remains user-scoped, project workspace saves backfill those associations from restore-relevant ids in the snapshot as a server-side safety net, project workspace reads now refresh generated-output delivery only from generation rows explicitly associated to that project, unsent Create/Edit/Video composer draft text plus unsent Sound workflow drafts are excluded from project workspace persistence, and the Media Library custom-folder area now scopes to the active project while `All Media` remains global. See `docs/sops/sop_ai_studio_projects_foundation.md` for the current shipped Projects contract and migration boundary.
- AI Studio style extraction helper route: authenticated `POST /api/ai/extract-style` extracts reusable style descriptors plus a creative style title from uploaded/dropped images used in Styles Library create flows, accepts the derived base64 `imageDataUrl` directly, and uses the structured OpenAI vision lane with server-owned retry/fallback handling.
- AI Studio safety-control runtime knobs are centrally gated: `STUDIO_AGENT_SAFETY_PROFILE_ACTIVE` (default `prod_safe_v1`), `STUDIO_AGENT_SAFETY_INPUT_PRECHECK_ENABLED` (default true, server pre-provider gate for `/api/ai/studio-agent-pulse`), `STUDIO_AGENT_SAFETY_INPUT_PRECHECK_GENERATION_SUBMIT_ENABLED` (default true), `STUDIO_AGENT_SAFETY_IMAGE_PREFLIGHT_ENABLED` (default true), `STUDIO_AGENT_SAFETY_IMAGE_PREFLIGHT_FAIL_MODE` (default `prod_closed_nonprod_open`), shared/scoped field-mode overrides (`STUDIO_AGENT_SAFETY_INPUT_PRECHECK_FIELD_MODES`, `STUDIO_AGENT_SAFETY_INPUT_PRECHECK_FIELD_MODES_STUDIO_AGENT`, `STUDIO_AGENT_SAFETY_INPUT_PRECHECK_FIELD_MODES_GENERATION_SUBMIT`), client mirrors (`NEXT_PUBLIC_STUDIO_AGENT_SAFETY_INPUT_PRECHECK_ENABLED`, `NEXT_PUBLIC_STUDIO_AGENT_SAFETY_INPUT_PRECHECK_FIELD_MODES`, `NEXT_PUBLIC_STUDIO_AGENT_SAFETY_INPUT_PRECHECK_FIELD_MODES_STUDIO_AGENT`), `STUDIO_AGENT_SAFETY_POSTPROCESS_MODE` (default `enforce`), `STUDIO_AGENT_SAFETY_DEV_ABSOLUTE_ZERO_ENABLED` (default false), `STUDIO_AGENT_SAFETY_PROVIDER_ERROR_MODE` (default `production_normalized`), `STUDIO_AGENT_SAFETY_AUTOROLLBACK_ENABLED` (default false), `STUDIO_AGENT_SAFETY_ROLLBACK_COOLDOWN_HOURS` (bounded `1..168`, default `24`), and control-plane runtime sync controls `STUDIO_AGENT_SAFETY_RUNTIME_CONTROL_PLANE_SYNC_ENABLED` (default true) plus `STUDIO_AGENT_SAFETY_RUNTIME_CONTROL_PLANE_CACHE_TTL_MS` (bounded `1000..60000`, default `5000`). Standard remains a raw pass-through route by explicit product decision and will not change until a future dedicated lane.

## Setup

1. Copy `frontend/.env.example` to `frontend/.env.local` (or export the values in your shell) and set:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `FAL_KEY`
   - `OPENAI_API_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `APP_BASE_URL`
   - `STRIPE_SECRET_KEY`
   - `STRIPE_WEBHOOK_SECRET`
   - optional mirror: `SHORTPULSE_PUBLIC_API_BASE_URL` only when it matches `APP_BASE_URL`
   - optional provider key for Kie routes: `KIE_API_KEY` (or `SHORTPULSE_KIE_API_KEY`)
2. Install and run the frontend:
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
   This starts the Next.js app, server API routes under `frontend/pages/api/*`, and the local generation control-plane worker that drains provider-accepted jobs into the canonical output/projection tables.

Auth/public-origin contract:

- `APP_BASE_URL` is the canonical server-side public origin for auth emails, Stripe redirects, and other server-generated URLs.
- `SHORTPULSE_PUBLIC_API_BASE_URL` is optional compatibility wiring only; when set, it must match `APP_BASE_URL`.
- Production must resolve to `https://www.shortpulse.ai`.

## Optional Supabase bootstrap

- Supabase tooling policy: use Supabase CLI for Supabase access and avoid Docker-based local Supabase workflows (`supabase start/stop`, `supabase db reset --local`, `supabase db lint --local`, or direct `docker` commands).
- Saved creators: run `sql/create_saved_creators_table.sql` to add the `saved_creators` table with RLS.
- Media library: run `sql/storage_policies.sql` to create the private `media_library` bucket and folder-scoped storage policies. The UI also expects a `media_files` table (see `docs/supabase_full_schema.sql` for a combined script).
- Private tab support: run `sql/migrations/003_add_private_media_source.sql` and `sql/migrations/004_add_private_media_integrity_checks.sql` to enforce `media_files.source` values and private path/file-type integrity.
- Billing + credits: run `sql/create_billing_credit_tables.sql` to provision plans, credit packages, billing profiles, ledger, and signup allocation triggers.
- Legacy billing environments: run `sql/migrate_ai_credit_ledger_legacy_to_v2.sql` to add `source/source_ref/metadata/created_by` columns and compatibility triggers before using `/admin` credit adjustments.
- App error telemetry: run `sql/create_app_error_logs_table.sql` and `sql/migrations/015_add_app_error_events.sql` to provision grouped incidents plus immutable per-occurrence events.
- SQL migration operations SOP: `docs/sops/sop_sql_migration_operations.md` (canonical run order, drift/repair loop, and common SQL error fixes).

## Security

- Only the Supabase anon key is used on the client; never share the service role key.
- Enable RLS on `saved_creators` and `media_files` (per-user isolation) and keep the `media_library` bucket private with paths prefixed by `auth.uid()`.
- Route protection: `/performance`, `/performance-soon`, `/saved-creators`, `/profile`, `/ai-studio`, `/creator-studio`, `/character`, `/character-soon`, and `/admin*` expect authenticated sessions and redirect to `/auth` when missing.
- API protection: announcement routes, provider proxy routes, media routes, billing routes, upload routes, and admin routes require bearer-authenticated Supabase sessions.
