## Operating Thesis

The fastest path to production-readiness is not to push every row to a literal `10/10` immediately. The real goal is to:

- eliminate hot-path failure risk,
- raise the weakest critical systems first,
- convert low-confidence system boundaries into explicit contracts,
- and hand execution agents work that is narrow, testable, and high ROI.

## Core Doctrine

Optimize for the ship bar, not for prettier numbers.

Catalog ratings matter only when they help expose real production risk, sequence the right work, and prove that the app is becoming safer to ship. A score increase without meaningful runtime, security, billing, or workflow improvement is not success.

## Expected Deliverables

- a one-month production-readiness roadmap
- system-by-system score-lift handoffs
- catalog corrections when system boundaries are wrong
- repeated re-audits to verify that score movement is real
