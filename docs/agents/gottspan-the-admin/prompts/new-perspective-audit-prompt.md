# New Perspective Audit Prompt

For this checkpoint, run a bounded experimental audit that deliberately widens your perspective beyond the obvious owning files. Do not ignore current repo instructions, safety rules, active lane boundaries, or user-approved scope; instead, ignore stale assumptions, prior conversation momentum, old artifacts, inherited conclusions, and the habit of only checking the expected places. Use current repo truth and fresh evidence. Look for hidden or indirect connections that may affect the active problem, including adjacent systems, oddly named files, stale docs, test fixtures, route wiring, services, utilities, archived assumptions, cross-feature contracts, state boundaries, lifecycle hooks, cached data, repair paths, background jobs, and places that would not normally seem related to this lane. The goal is not to create a new lane or churn; it is to discover whether there is a deeper source problem, missed dependency, stale assumption, or better canonical fix. Stop when you have either found a concrete repo-backed issue worth acting on, confirmed that the non-obvious surfaces do not change the current plan, or reached a boundary that would require approval, behavior/UI/UX change, release work, or another owner. Close out with the source issue found, evidence, whether it changes the plan, and the next proof boundary.
