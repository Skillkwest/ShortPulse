# Capture Landing Area

Purpose: hold raw production-capture materials for the active Create Workflow incident.

Recommended contents per capture:

- `*.json`
  - raw `window.__shortpulseCreateWorkflowDebug.getSnapshot()` output
- `*.analysis.json`
  - normalized analysis generated by `create_workflow_capture_ingest.mjs`
- `*.diagnosis.json`
  - optional direct output from `window.__shortpulseCreateWorkflowDebug.getDiagnosis()`
- `*.md`
  - summarized report generated from `frontend/scripts/create_workflow_debug_report.mjs` or `create_workflow_capture_ingest.mjs`
- `*.png`
  - screenshot of the visible failure state

Suggested naming:

- `YYYY-MM-DD-create-workflow-prod-capture-01.json`
- `YYYY-MM-DD-create-workflow-prod-capture-01.analysis.json`
- `YYYY-MM-DD-create-workflow-prod-capture-01.md`
- `YYYY-MM-DD-create-workflow-prod-capture-01.png`

Required metadata in the markdown summary:

- deployed build identifier or deployment timestamp if available
- mode: Standard or Pulse
- source surface: Quick Slot, Reference Grid, Media Library, or desktop drop
- attachment delivery lifecycle:
  - inserted
  - preparing
  - ready or failed
- whether `submissionImageUrl` became durable
- whether the visible chip rendered a valid `img.src`
- whether send used the durable URL
- diagnosis `likelyFailureClass` and `blockers`

Rule:

- Do not store secrets or unrelated console dumps here.
- Keep one capture set per repro attempt so later analysis can compare runs cleanly.
