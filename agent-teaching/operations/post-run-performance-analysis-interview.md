# Post-Run Performance Analysis Interview

Purpose: review a supervised run, expose friction, and turn the findings into better docs, prompts, tools, and trigger phrases.

This should be a real dialogue, not a fake pass/fail ritual.

## Run The Interview In Order

### 1. Ask About The Run Experience

```text
How did that feel? What parts felt heavy, confusing, brittle, or hard to judge? Where did you have to improvise?
```

### 2. Ask About Scope Split

```text
Should this workflow stay in one agent, or should it split into multiple agents with narrower responsibilities?
```

### 3. Ask For A Performance Rating

```text
Rate your performance on this task out of 10.
```

### 4. Ask What Would Raise It To 10

```text
What would need to change to get this workflow to 10/10 performance?
```

### 5. Ask About Missing Tools Or Resources

```text
Do you need any new tools, skills, scripts, references, checklists, or supporting resources to do this correctly every time?
```

### 6. Ask Whether Memory Needs Updating

```text
Do we need to update your memory, reports, or training-history based on what happened in this run?
```

### 7. Create A Trigger Phrase

```text
Create a trigger phrase I can use when I want you to run this SOP again.
```

### 8. Turn The Discussion Into Repo Changes

```text
Utilize all the details we have discussed and create everything you need. Update any relevant docs or artifacts. Make sure your SOPs reflect the correct changes we need to achieve 10/10 performance on this task. Audit and update your SOPs.
```

### 9. Systematize The Interview

```text
Systematize this interview into a reusable doc so we can run it after future supervised runs.
```

## Expected Outputs

The interview should improve at least some of:
- the SOP
- the trigger phrase
- the training-history
- the contract
- helper scripts or tools
- escalation rules
- the decision to split one agent into several
