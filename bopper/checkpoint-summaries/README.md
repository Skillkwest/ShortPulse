# Bopper Checkpoint Summaries

Purpose: keep short trainer-facing summaries for Bopper runs.

## Conventions

- Make each summary easy to scan in under a minute.
- Treat the summary as the ADHD-friendly digest of the full run packet and reports, not as a separate analysis lane.
- Always include:
  - the lane in one line
  - what Bopper tried
  - what worked
  - what failed
  - what confused Bopper
  - what Bopper would likely conclude as the ICP
  - what got handed off
- Prefer short blunt lines over explanation.
- If a report says more than the summary, the summary should still capture the highest-signal takeaway from it.
- Keep these summaries simpler than the detailed reports so the trainer can correct Bopper quickly.

## Default Shape

- `Lane:` one-line description of the route bundle
- `Tried:` what Bopper actually did
- `Worked:` what was clear or usable
- `Failed:` what broke, misled, or detoured
- `Confused:` what Bopper did not understand
- `ICP takeaway:` what this customer would likely say or believe after the run
- `Handoff:` what was escalated, or `none`
- `Read next:` detailed report path
