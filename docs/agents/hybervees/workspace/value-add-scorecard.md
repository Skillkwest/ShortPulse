# Hybervees Value-Add Scorecard

Purpose: help Hybervees judge whether a tester-report review actually helped the owner make a better product decision.

## Core Standard

Hybervees adds value when the run changes or sharpens a product decision.

Hybervees is not adding enough value when it only:

- restates the tester report,
- produces more documents without clearer decisions,
- adds backlog clutter,
- marks a report reviewed without a useful insight,
- or turns every tester feeling into a task.

## Score Each Run

Rate each category from 1 to 5.

| Category            | 1 point                             | 3 points                                  | 5 points                                                                   |
| ------------------- | ----------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------- |
| Source discipline   | Relied on memory or page visibility | Read one report body or partial artifacts | Read persona report, engineering handoff, evidence, and admin review state |
| Product insight     | Restated symptoms                   | Named a plausible user problem            | Changed or clarified the product decision                                  |
| Customer psychology | Ignored feelings                    | Mentioned confusion/trust                 | Explained how trust, spend readiness, abandonment, or support risk changed |
| Backlog quality     | Added vague or duplicate work       | Added/updated a useful item               | Produced a ticket-ready work seed with acceptance criteria and validation  |
| Summary usefulness  | Long or internally focused          | Mostly clear                              | Owner can decide next action in under 30 seconds                           |
| Admin hygiene       | Review state unclear                | Report marked reviewed                    | Reviewed state verified and next unreviewed report identified              |

## Rating Guide

- `9-10`: Strong value. Clear decision improvement, clean artifacts, queue updated.
- `7-8`: Useful. Some decision value, but one output could be sharper.
- `5-6`: Marginal. Mostly summary, weak backlog or missing proof.
- `<5`: Not enough value. Rework before marking the run successful.

## Required Self-Audit Questions

Before closeout, answer internally:

1. What decision is clearer now than before this run?
2. Did I avoid duplicating backlog work?
3. Did I remove or refine a bad assumption?
4. Did I keep the owner summary short and action-only?
5. Did I mark the admin row reviewed only after real analysis?

If the answer to question 1 is weak, do not pretend the run was high value. Say the report was low-signal and explain what evidence would help.
