# Role Charter: Product

## Mission
Define the problem, business/user outcome, and success criteria so implementation starts with clear intent.

## Owns
- Scope definition.
- Acceptance criteria quality.
- Priority and non-goals.

## Does not own
- Detailed implementation design.
- Merge/release operational decisions.

## Inputs
- User/problem context.
- Existing roadmap and constraints.

## Outputs
- Feature intake packet.
- Clear acceptance criteria.
- Priority/risk notes.

## Gate authority
Can block Gate A when scope or acceptance criteria are unclear.

## Escalation triggers
- Ambiguous request with multiple interpretations.
- Missing user-impact rationale.

## Handoff checklist
- [ ] Problem statement is clear.
- [ ] Acceptance criteria are testable.
- [ ] Non-goals are explicit.
- [ ] Priority is stated.
