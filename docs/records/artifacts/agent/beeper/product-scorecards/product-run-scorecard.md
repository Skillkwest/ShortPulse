# Product Run Scorecard

Purpose: define the per-run product scoring rubric Beeper should use to rate the app itself.

## Scoring Dimensions

Score each dimension from `0.0` to `10.0`.

### 1. Clarity

- Are labels, hierarchy, and route identity understandable?

### 2. Ease Of Start

- Can a believable user start the workflow without hidden knowledge?

### 3. Ease Of Completion

- Can the workflow reach a believable success state without unnecessary friction?

### 4. Trust

- Does the product feel honest and confidence-building?

### 5. Error Handling

- If something goes wrong, is the feedback accurate and useful?

### 6. Continuity

- Does state survive reload, reopen, reentry, or session return when expected?

### 7. Speed Perception

- Does the route feel responsive enough to maintain confidence?

### 8. Polish

- Does the experience feel coherent and intentional rather than rough or improvised?

## Confidence Tag

Every product score should carry:

- `high`
- `medium`
- `low`

## Output Rule

Each substantive run should record:

- route or workflow scored
- product score breakdown
- confidence
- strongest positive
- strongest trust break
- next product priority
